# GitHub Communication Guidelines

## Language Requirements

**ALL GitHub comments, issues, pull request descriptions, and commit messages MUST be written in English**

This applies to:

- Issue descriptions and comments
- Pull request descriptions and review comments
- Commit messages
- Code review feedback
- Discussion threads
- Release notes

## Rationale

- Ensures all team members can understand and participate in discussions
- Maintains consistency across the project
- Facilitates collaboration with international contributors
- Aligns with industry best practices for open-source projects

## Exceptions

- Code comments and documentation can use the language appropriate for the codebase context
- Internal team communication outside of GitHub (Slack, email, etc.) can use any language
- Variable names, function names, and code should follow the project's coding standards (typically English)

## Issue writing

When creating or editing GitHub issue descriptions:

- **Do not include** estimate/estimation fields or time guesses.
- **Avoid code examples** unless they are strictly necessary to describe the problem or expected behaviour; they tend to be misread or over-specified.
- **Avoid subjective wording** (e.g. "it would be nice", "we could"); state **concrete expectations** for what the change will achieve or how behaviour will differ.
- **Requirements / acceptance criteria**: write them inline in the issue body (e.g. in the same paragraphs or list), not in a separate "Requirements" or "Acceptance criteria" block that duplicates or splits the same content.
