The writer of an entry is never its approver.

Nothing leaves without a yes.

Agents create and edit calendar entries. They never publish and never approve. When an approved entry is due, a scheduler hands it to a connector.

Low-risk entries can pass on their own, others wait for one click, and anything sensitive needs a deliberate manual approval. When unsure, the higher tier wins.

Whoever writes an entry can never approve it, and every approval records who gave it and why. Approval is a role: a person or, by design, a dedicated approver agent working under a policy set per campaign.

Today every approval above tier 1 is given by a person in the Calendar page. Approver agents and their policies are designed but not built yet, so by default every tier above 1 waits for a person.

Agents propose. Code decides.

Every page has an agent that knows which campaign and project you are looking at. It drafts, generates creatives, edits video and reads the results, using the same commands you can run yourself.

Agents get tools, not credentials: they use the bb brandwise CLI, also reachable over MCP, and "Start agent" sits in the side panel of every page.

For e-mail an editor agent closes the loop: it reads the numbers, runs one A/B test at a time and briefs author agents. Code judges the result (sample size, significance, complaint guards); only you set the goals.

API keys stay in settings and are never shown to it. Failed sends retry, then surface in the calendar with the reason.

Swap providers. Keep your numbers.

Opens, clicks and bounces are computed from your own records in one provider-neutral format, so replacing the e-mail provider does not break a single report. A metric a provider cannot report shows as n/a, never as a made-up zero.

The editor loop, judged by code.

The editor agent picks one hypothesis at a time and author agents write the variant, which goes out through the same calendar as everything else. Code judges the result: maturity, minimum sample, significance plus a minimum lift, cooldown, complaint and unsubscribe guards.

Only a person sets the goals and clears a freeze. The whole loop is testable in minutes on a simulated provider and clock.

What is in the box.

BrandWise is an open-source, agent-driven marketing system that runs on bb.

Campaigns

An always-on base for a brand or product, plus time-bound campaigns that inherit from it.

Calendar

Month and week views, an approval queue, change requests, retries and failure reasons.

Publishing

calendar run-due fires every minute as a bb automation. Connectors for Telegram, e-mail (Resend) and a mock test connector; channels without a connector wait as "Publish by hand".

Creatives

A library of images and videos in S3 with thumbnails, AI provenance, upload and editing. Higgsfield image and video generation with per-call and daily credit limits.

Video Optional

Remotion projects per campaign, with Remotion Studio embedded next to an agent chat. Renders land in Creatives.

E-mail templates Optional

MJML templates per campaign with slots and a brand file, a live preview page and lint (unsubscribe, postal address, size, alt text, links, ...). Full-page pictures for agents, test sends, and an agent that edits the template while you watch.

Installed with one command.

npx create-brandwise asks a few questions, then installs bb if it is missing, clones BrandWise, installs the dependencies, writes .env and provisions the instance.

  1. Postgres and S3Local in Docker, remote, or already running.
  2. Publishing channelsOptional Telegram and Resend keys; they can be added later.
  3. Display modeMinimal (marketing only) or full.

Requirements: one machine on macOS or Linux, Node 24, pnpm, Docker, bb 0.48 or newer.

Installation guide

Fully yours.

One command, npx create-brandwise, installs it on your machine with a local or your own Postgres and any S3-compatible storage. Campaigns, calendar, creatives and statistics stay with you.

It is MIT licensed. Add a channel with one small connector, an e-mail provider with one adapter file, and make the rest your own.
